# UI-архитектура и отчёт по файлам

В `website/src/components/` находятся 28 Astro-компонентов, без вложенных папок. Страницы собирают их и задают метаданные. Публичные API не принимают `style`, `class`, `className`, CSS-объекты или произвольные атрибуты. У каждого компонента есть отдельный файл истории в `website/stories/`.

## Граница ответственности

Компонент владеет своим фоном, типографикой, рамками, размерами интерактивных элементов, внутренними отступами и состояниями. `Wrapper` выделяет место среди соседей: направление, сетку, отступы вокруг, выравнивание и позиционирование. У Wrapper нет селекторов потомков и параметров оформления.

```astro
<Wrapper margin="1.5rem 0 0" at={{ large: { margin: '2.25rem 0 0' } }}>
  <ActionLink variant="primary" href={whatsappUrl} fullWidth external>
    Узнать цену и наличие
  </ActionLink>
</Wrapper>
```

`dir` автоматически включает flex, `grid` — grid. `at` содержит частичные изменения layout на брейкпоинтах `small` (480), `tablet` (640), `medium` (768), `laptop` (900), `large` (1024), `desktop` (1200), `wide` (1280), `cinema` (1440). Значения заданы в rem; числа для расстояний интерпретируются как px.

Wrapper генерирует внутри себя короткий stylesheet, ограниченный собственным детерминированным атрибутом. Он работает без JavaScript и не передаёт настройки вложенным обёрткам. Разрешённые CSS-свойства перечислены явно; дополнительные декларации в значениях отклоняются. Это внутренний механизм layout-компонента, а не публичный style API.

## Storybook

Запуск из корня репозитория с Bun из `.bun-version`:

```sh
bun run storybook
bun run build:storybook
```

Первая команда запускает Storybook на `http://127.0.0.1:6006` и отдельный Astro-каталог на порту 4322. Supervisor использует программный API Astro и закрывает оба процесса по Ctrl+C. Для окружений без файловых событий включён polling. Порты фиксированы; занятый порт Astro приводит к понятной ошибке вместо незаметной смены адреса.

Вторая команда создаёт автономный `website/storybook-static/`. Истории показывают настоящую сборку Astro с её изображениями, scoped CSS и скриптами, без React-копий. 47 историй имеют 28 страниц документации; 66 отрисованных примеров включают комбинации controls. Controls ActionLink поддерживают все 18 сочетаний variant/size/fullWidth. Остальные истории задают фиксированные содержательные примеры, включая пустой аккордеон, открытый пункт, брендированный вопрос, отсутствующий состав и разные каналы покупки.

`catalog/` — отдельный srcDir. Примеры не становятся маршрутами основного сайта. Их props проверяются через `ComponentProps` исходных Astro-компонентов. Для автономной библиотеки применяется собственный SAMEORIGIN-заголовок: политика DENY основного сайта иначе блокировала бы внутренние iframe. Заголовки основного сайта не изменены.

Новый компонент нужно добавить в типизированный `catalog/examples.ts` и создать `stories/Имя.stories.ts`. История ссылается на реальный пример через `renderExample`, а не копирует HTML/CSS. Для размерного контекста примера используйте preview-layout через Wrapper.

## Проверки и ограничения

- `bun run check:ui`: 28 плоских компонентов, у всех есть история; нет косметического passthrough, непроверенного spread в UI-компонентах, локальных CSS страниц/layout и внешних global-переопределений.
- Разрешённые `:global` ограничены явно перечисленной разметкой, создаваемой внутри владельца: raw SVG, Picture и маски SplitText. Это не доступ к другим UI-компонентам.
- `bun run typecheck`: автоматически запускает архитектурную проверку перед Astro/TypeScript; без ошибок, предупреждений и подсказок.
- `bun run build`: три публичные страницы.
- `bun run build:storybook`: успешная автономная сборка; все ссылки на сгенерированные ресурсы примеров разрешаются.
- `git diff --check`: без ошибок пробелов.
- В Chrome проверены production-разметка, desktop 1400 px и mobile 390 px, открытие/закрытие меню с Escape, карусель и состав, FAQ с клавиатурой, подсказки медовика. Геометрия основных секций сравнена с исходной: в desktop-снимке отклонение не превышает 0.5 px после завершения анимаций.
- В Storybook проверено реальное изменение data-variant Astro-ссылки при переключении control. Также проверен HMR: изменение текста исходного примера появилось без перезагрузки; исходный текст восстановлен.

Проверки выполнялись на свежем production build: фоновый dev-server в данном окружении не всегда получал файловые события. Тестового раннера в репозитории по-прежнему нет. Проверка архитектуры анализирует AST и известные границы; она не заменяет визуальный review произвольных будущих изменений.

Storybook сообщает о крупных чанках своего UI при сборке. В ограниченном окружении также может сообщать о невозможности сохранить глобальные настройки в домашней папке. Это не мешает сборке или отрисовке компонентов. Проверка типов исключает `dist`, `storybook-static`, fixtures и cache, чтобы не анализировать сгенерированный код.
