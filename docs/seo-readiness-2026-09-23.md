## Статус

Подготовка и проверки выполнены. Текущий технический домен намеренно закрыт от индексации. Подключение брендового домена, публикация, Search Console и Яндекс Вебмастер не выполнялись. Новые товарные страницы не создавались.

**Полная готовность по целям PRD пока не подтверждена:** мобильный Lighthouse Performance 88 при целевом значении 90. Это измеренный результат, а не обещание показателей после публикации.

## Реализовано

- Проверка ровно одного непустого title, description и H1; единственного корректного canonical; отсутствие дублирующих или противоречащих crawler meta-директив.
- Строгий разбор sitemap как XML, проверка namespace, структуры, дублей и точного набора канонических URL. Закрытый режим требует пустой набор; открытый — `/` и `/privacy/`, без 404.
- Проверка JSON-LD: JSON, контекст, типы Bakery/LocalBusiness, URL, название, адрес, телефоны и ежедневные часы работы; сравнение с содержимым страницы и контактными ссылками. Необязательные поля не требуются. Это локальная проверка, не результат Google Rich Results Test.
- Регрессионные тесты на неверный canonical, дубли, noindex в открытой сборке, конфликт robots, повреждённый XML, лишние URL и расхождения schema с контактами.
- Исправлена чувствительность существующей проверки `_headers` к CRLF на Windows.
- Исправлена горизонтальная прокрутка privacy на мобильной ширине: длинные слова могут переноситься внутри блока содержимого. Предшествующие пользовательские изменения реквизитов сохранены.
- README уточняет build-time характер SEO-переменных и production-ветку `main`.
- `sax@1.6.1`, уже присутствовавший транзитивно, закреплён прямой dev-зависимостью для XML-парсера. Новых production-зависимостей нет.

## Оставшиеся ограничения

1. **Производительность:** LCP-элемент — изображение торта первого экрана. Lighthouse указывает задержку начала загрузки, блокирующие CSS (расчётная экономия около 150 мс) и цепочку зависимостей. Следующий этап оптимизации должен опираться на waterfall и повторный замер; сам размер PNG fallback не доказывает медленную загрузку, поскольку браузер выбирает AVIF.
2. **Контраст:** у года, счётчика и «Читать далее» в истории бренда измерен контраст 2,89:1 (`#d47212` на `#f4ece6`), ниже 4,5:1 для этого размера текста. Accessibility 96 превышает общий порог 90, но проблема остаётся.
3. **Запуск:** выбрать брендовый домен; настроить DNS/TLS и постоянный редирект с технического домена с сохранением пути и query; перед сборкой задать финальный origin и indexing=true. Preview оставить закрытым. Проверить опубликованные HTTP-ответы, canonical, OG, schema, robots и sitemap; затем подтвердить домен в поисковых кабинетах и отправить sitemap. Через 1–2 недели проверить статус индексации и выбранные canonical.
