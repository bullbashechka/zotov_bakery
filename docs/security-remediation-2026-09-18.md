## Принятые технические решения

- Скрипты: только локальные ресурсы и точные хеши; нет `unsafe-inline` или
  `unsafe-eval`, `script-src-attr 'none'`. Хеши двух ранних inline-скриптов
  вычисляются из тех же исходников, которые вставляются в HTML. Остальные
  build-generated scripts учитывает Astro; итоговый HTML проверяется отдельно.
- Стили: осознанно разрешены inline styles для существующего Wrapper и
  анимаций. Это исключение только для CSS, не для JavaScript. Сам Wrapper и его
  layout-семантика не изменены. Более строгие style hashes — отдельная задача,
  а не повод переделывать layout непосредственно перед выпуском.
- Report-Only проверен локально на том же HTML через перехват ответа браузером,
  затем проверено enforcement. Это не развёртывание Report-Only на настоящем preview.
- SVG-проверка — консервативный барьер для доверенных исходников репозитория,
  не универсальный sanitizer. Запрещены scripts, foreignObject, event handlers,
  внешние ссылки, DTD/entities, SMIL-мутации, CSS escapes и неожиданные элементы.
- Secret scan не выводит значения находок. Бинарные/крупные файлы исключаются;
  проверяется доступная локальная Git-история, не неизвестные удалённые хранилища.
- Релизный барьер останавливается при любой неуспешной стадии. Deploy-wrapper
  проверяет чистоту дерева, ветку, origin remote и HEAD до и после проверок,
  затем передаёт Wrangler только фиксированный каталог артефакта.

## Проверки

Команда локальной приёмки:

```bash
PUBLIC_WEBSITE_URL=https://zotov-landing.pages.dev bun run release:check
```

Это тестовый origin, не заявление о существовании или владении этим доменом.

- `bun audit`: exit 0, известных уязвимостей не найдено.
- Frozen install и проверка 10 точных установленных версий: успешно.
- 50 Node-тестов: успешно, включая отрицательные тесты scanner/CSP/SVG/origin
  и проверки, что ошибочная стадия не вызывает deploy. Deploy в тестах замокан.
- `bun run typecheck`: 87 файлов, 0 ошибок/предупреждений/hints.
- Сборка: четыре страницы; проверка 169 файлов output пройдена.
- Отдельная сборка во временной копии без image cache: все 100 вариантов
  изображений созданы заново, проверка её артефакта также успешна.
- Локальный Pages: главная и legal-страницы — 200; неизвестная страница,
  `/.env`, `/.git/config`, `/api/test`, отсутствующие JS/изображения — 404;
  защитные заголовки присутствуют.
- Chromium: 390/1440 px, Report-Only и enforcement; меню/Escape, FAQ,
  клавиатурное переключение товара, legal и 404. Нет обычных CSP violations,
  ошибок JavaScript и неожиданных внешних запросов. Включённые анимации проверены
  отдельно. Тестовый inline JS и внешний JS блокируются CSP.
- Визуальное сравнение с HEAD: desktop совпал попиксельно; на mobile после
  завершения загрузки/пересчёта отступов в трёх независимых контекстах совпали
  высота документа и геометрия всех секций/подвала. Нестабильный ранний снимок
  оказался промежуточным состоянием, поэтому screenshot smoke теперь ждёт
  завершения загрузки, шрифтов и пересчёта layout и сбрасывает scroll в начало.
- GitHub Actions добавлен и SHA используемых actions сверены с upstream tags;
  workflow пока не запускался на GitHub. Локальный прогон не подменяет Linux CI.

Astro выводит предупреждение о стандартном Shiki/CSP; Markdown-подсветка в
публикуемых страницах не используется, браузерные проверки нарушений не показали.

## Что остаётся перед production

1. Завершить S04: согласованные тексты политик вместо заглушек.
2. Указать настоящий `PUBLIC_WEBSITE_URL`; проверить DNS/TLS/redirect/HSTS,
   CSP и 404 на настоящем Pages preview и production edge.
3. Включить required checks/branch protection и связать Cloudflare Git integration
   с релизным барьером: один workflow сам по себе не запрещает независимый автодеплой.
4. Проверить доступы/MFA, возможные edge-инъекции Analytics/Zaraz, мониторинг,
   rollback и реалистичный пик кампании. Локальная сборка не является нагрузочным
   подтверждением готовности к 24 000 пользователям.

Отдельное наблюдение: `/_headers` всё ещё даёт 502 в локальном Wrangler 4.124.0.
Подтверждена причина в эмуляторе: попытка `lstat` для `_headers/index.html`
под обычным файлом вызывает `ENOTDIR`. Содержимое файла не раскрывается;
источник `_headers` и его копия в output совпадают. Обходной маршрут в приложение
не добавлен. Ответ реального Cloudflare остаётся проверить после разрешённой
публикации. Это не объявлено доказанным production-дефектом.

Итог: технические изменения репозитория реализованы и локально проверены.
Безусловный production GO не выдан: перечисленные внешние проверки и отложенные
политики остаются обязательными перед запуском.
